# V0.2 — BOSS 登录连接（Raw CDP）

状态：

**已完成 / 已冻结**

Git Tag：

```text
v0.2.0
```

目标：

> 让 JobPilot 可以建立并持久保存由用户本人完成的 BOSS 登录 Session。

范围：

* 真实 Google Chrome + 独立持久化 Profile
* Raw CDP Browser Driver（ChromeCDPManager / RawCDPClient）
* BOSS 独立 persistent Browser Profile
* TEST / PRODUCTION Browser Profile 隔离
* 打开可视化 BOSS 登录页面
* 用户手动完成扫码 / 短信 / CAPTCHA
* 只读登录状态检查（不导航 / 不创建页面）
* Browser Profile 持久保存登录信息
* 平台连接状态管理
* 检查连接
* 重新连接
* 断开连接
* 清理 JobPilot 管理的 BOSS Profile
* Electron IPC 接入
* Windows 打包后的兼容性验证

明确不包含：

* 岗位搜索
* 岗位列表解析
* JD 解析
* AI 岗位评分
* 自动投递
* HR 消息读取
* 自动发送消息
* CAPTCHA 或安全机制绕过
* 反检测 / stealth

验收链路：

```text
连接 BOSS
↓
用户手动登录
↓
JobPilot 确认连接
↓
关闭 JobPilot
↓
重新启动
↓
Browser Profile 仍然存在
↓
Session 可以继续使用
↓
可以检查当前连接
↓
断开连接后清除 JobPilot 管理的认证数据
```

## V0.4-D — LLM 语义决策升级（已完成）

状态：

**已完成并提交（V0.4.0 Release）**

已完成：

* LLM Provider 抽象（core/decision/provider）：输入输出契约与本地引擎一致，可替换实现
* DeepSeek Provider（deepseek-chat，OpenAI 兼容 HTTP）：结构化提示词（候选人资料 + 求职规则 + 完整 JD）→
  严格 JSON 输出（verdict / matches / risks / unknowns / reason / confidence），zod 校验 + 容错解析
* 决策流程：配置了 API Key → LLM 语义判断（方向 / 技能 / 风险 / 不确定项 / 简短理由）；
  未配置或 LLM 调用失败 → 自动回退本地规则引擎（可用性保证）
* 硬规则护栏（产品铁律）：用户明确硬规则（城市 / 薪资 / 外包 / 单休 / 排除词 / 学历经验严格模式）
  优先级高于 LLM —— LLM 结果若违反 → 强制 SKIP 并列出违反项
* 防编造约束：系统提示强约束「只能使用提供的信息；简历没写≠不会 → 不确定时 REVIEW」
* 模型配置：Settings「AI 模型」区（API Key / 模型名，Key 仅存本机数据目录，禁止提交 Git）；
  AI 配置与决策结果复用 / 过期机制不受 Provider 影响
* 自动测试：mock Provider 流程（LLM 生效 / 护栏强制 SKIP / LLM 失败回退 / 未配置回退 / 复用过期）+
  真实 DeepSeek API 冒烟脚本（deepseek:smoke，需 JOBPILOT_DEEPSEEK_KEY 环境变量）
* 已知限制：远程 API 会把候选人资料与 JD 发送给模型服务商（设置页明示）；LLM 输出质量取决于模型，
  硬规则护栏保证用户明确条件不被 AI 覆盖

明确不包含：

* 自动投递 / HR 消息
* 简历改写
* 多模型自动切换（当前固定 DeepSeek，Provider 接口已支持后续扩展）

## V0.4-A — Candidate Profile / 简历基础能力（已完成）

状态：

**已完成并提交（V0.4-A checkpoint）**

已完成：

* 简历上传 / 查看 / 更换 / 移除（PDF / DOCX，本地解析，不依赖第三方服务）
* 版面结构解析（V0.4-A 解析架构调整）：PDF 先还原「内容块 + 视觉顺序」，再按 Section 语义识别，
  不依赖固定模板 / 固定左右布局 / 固定栏目名（教育背景/学历信息、实习经历/职业经历、专业技能/技术能力等同义标题均可识别）
* 简历纯文本本地提取（PDF：pdfjs 版面行重建，保留行内字段间隔；DOCX：mammoth 段落序列）
* 规则解析器：姓名 / 电话 / 邮箱 / 工作年限 / 教育背景 / 工作与实习经历 / 项目经历 / 技能 / 证书 / 语言能力 / 自我评价
* 解析只提取简历原文，不编造简历中不存在的信息；结构化字段与原文保持对应关系
* 教育经历：多段分别解析、多行版式（学校/时间/专业/学历分行）合并、tab 字段行（学校|专业|学历|时间）识别、无法确定留空
* 工作 / 实习经历：每段独立记录（时间在左 / 在右、公司+右侧时间、多行条目标题均支持），公司 / 职位 / 时间 / 内容对应，内容不串段
* 技能解析：从技能描述中识别技术实体 / 能力短语（Python、Pytest、Selenium、Java、Java单元测试、PO模式、CI/CD、Docker…），
  过滤序号 / 连接词 / 描述性动词 / 被拆开的 CI/CD / 无独立意义的普通词
* 解析完整性提示（warnings）：检测到某部分但未识别完整时提示用户手动补充，用户确认后清空
* 「我的资料」页面：当前简历状态、候选人资料只读视图、可编辑修正、保存确认、解析不完整提示
* 更换简历明确提示会重新生成候选人资料；资料过期时明确提示并需用户确认后重新解析
* 原始简历与结构化资料均持久化（SQLite，userData 目录），TEST / PRODUCTION 隔离
* 自动测试：解析器多样式回归（单栏/双栏阅读顺序/时间左右/多段教育实习/技能列表/自然语言段落/不同栏目名）+
  全链路持久化测试 + 用户真实简历 PDF 端到端回归

## V0.4-B — AI 岗位决策引擎（单岗位，已完成）

状态：

**已完成并提交（V0.4-B checkpoint）**

已完成：

* 求职规则设置（Settings「求职规则」）：目标岗位方向 / 接受城市 / 最低薪资 / 是否接受外包 / 单双休 /
  学历与经验容忍度 / 明确排除关键词；用户的明确规则优先级高于引擎判断
* 本地可解释岗位决策引擎（core/decision，纯函数、确定性、可测试；预留后续替换为 LLM Provider）：
  - 只使用 确认后的 Candidate Profile + 求职规则 + 岗位完整 JD，不调用外部服务
  - 硬规则违反 → SKIP（城市 / 薪资 / 外包 / 单休 / 学历与经验严格模式 / 排除词）
  - 明显符合 → AUTO_APPLY；存在关键风险 / 不确定 → REVIEW（不确定时宁可 REVIEW，不擅自 AUTO_APPLY / SKIP）
  - 「简历没写」≠「用户不会」：JD 要求但资料未体现 → 进入 REVIEW 而非臆断
  - 决策理由为模板化短句：主要匹配点 / 主要风险 / 关键不确定项 / 简短决策理由（可展开查看）
  - 内部匹配分与置信度仅作参考，不是产品核心
* 决策结果持久化：同一岗位复用已有结果；支持主动重新分析；
  Candidate Profile / 求职规则 / JD 变化后旧结果明确标记过期并给出具体原因
* Jobs 工作台详情区「JobPilot 决策」模块：单岗位分析，不做批量
* 自动测试：决策引擎三类验收场景（AUTO_APPLY / SKIP / REVIEW + 防编造）+ 持久化 / 复用 / 过期测试

## V0.4-C — 批量自动岗位决策（已完成）

状态：

**已完成并提交（V0.4-C checkpoint）**

已完成：

* 「分析本次新岗位（N）」入口（Jobs 工作台批量决策卡）：只处理「最近一次搜索运行」（一次手动搜索 / 一次自动搜索计划）发现的全部 NEW 岗位，历史积压岗位不混入
* 批量流程：NEW 岗位 → 获取完整 JD（已有直接使用，缺失自动读取 BOSS 详情）→ V0.4-B 决策 → 分三类
* 实时进度与汇总：总岗位 / 待分析 / 适合自动投递 / 需要确认 / 已跳过 / 失败；
  统一状态模型严格满足 总岗位 = 待分析 + 适合自动投递 + 需要确认 + 已跳过 + 失败，统计与队列一致
* 平台安全（不绕过）：缺 JD 的岗位有节制地顺序读取（详情间节流延迟，禁止高频连续访问）；同一岗位读取失败后不立即重试（失败标记，可后续重新处理）；
  读取结果明显不是有效详情（JD 过短）→ 不决策、标记失败；平台安全验证 / 登录失效 / 连接断开 → 该岗位跳过继续，任务不中断
* 中途停止（CANCELLED）保留已完成结果；继续 / 再次分析只处理剩余岗位，已完成决策不重复
* REVIEW 队列（本阶段最重要入口）：只列出需要用户决定的岗位，可「允许投递 / 跳过」，
  仅改变决策状态（user_action），不真正投递
* AUTO_APPLY 仅进入待投递队列（本阶段不点击 BOSS 投递）；SKIP 岗位降权但不删除岗位历史
* 已分析岗位不重复分析：已有有效决策跳过；仅资料 / 规则 / JD 变化（过期）或用户主动才重新分析
* 统计避免重复：同一岗位多任务发现只算一次（platformJobId 去重），
  口径一致 总岗位 = 待分析 + AUTO_APPLY + REVIEW + SKIP + FAILED
* 自动测试：批量分析全链路（去重 / 失败跳过继续 / 取消保留 / 不重复分析 / REVIEW 用户处理 / 统计一致性与恒等式）

明确不包含（后续版本）：

* 真正自动投递 / 自动发 HR 消息 / 自动打招呼
* LLM Provider 扩展
* 自动修改简历
* 完整「投递中心」UI

预计能力（V0.5）：

* 受控自动投递流程（AUTO_APPLY 队列）
* 投递上限 / 防重复投递 / 日志
* TEST / PRODUCTION 投递行为隔离

重要原则：

用户明确设置的硬条件优先级高于 AI 判断。

例如：

```text
最低薪资
排除销售
排除行业
城市
单双休
外包偏好
```

AI 不只输出：

```text
87分
```

还必须解释：

> 为什么值得投 / 为什么不建议投。

# 版本发布纪律

每一个版本按照：

```text
开发
↓
定向测试
↓
回归检查
↓
Lint
↓
TypeCheck
↓
Build
↓
Dist
↓
必要的人工验收
↓
Commit
↓
稳定版本按需创建 Tag
```

不要因为下一版本“看起来很简单”，就在当前任务中顺手实现。

宁可：

> 小版本完整、稳定、可验收

也不要：

> 大版本功能很多但只有一半可靠。
